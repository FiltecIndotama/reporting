SECTION 01

What you are editing

The entire website is one file: filtec-sales-dashboard.html. Everything lives inside it — HTML, CSS in a single <style> block near the top, and JavaScript in a single <script> block at the bottom. There is no framework, no npm, no build step. What you commit is what the browser runs.

Two external scripts load at the end (/view-counter.js, /sw-register.js). You never need to touch them to add a tab.

SECTION 02

How a tab actually works

There is no router and no framework. Tabs are CSS visibility, nothing more. Every tab is two pieces of HTML that share a number:

<button class="tab-btn"  id="tab-8" onclick="setPage(8)">   ← the button
<div    class="page-panel" id="page-8">                ← the content

All panels are always in the DOM. Only the active one is visible, because of two CSS rules:

.page-panel        { display: none;  }
.page-panel.active { display: block; }

And one JavaScript function that moves the active class around:

function setPage(n) {
  [1, 2, 3, 4, 5, 6, 7, 8].forEach(function(i) {
    document.getElementById('page-' + i).classList.toggle('active', i === n);
    document.getElementById('tab-'  + i).classList.toggle('active', i === n);
  });
  window.scrollTo({ top: document.querySelector('.tabs-bar').offsetTop, behavior: 'smooth' });
}
The one thing that trips everybody up

That array [1, 2, 3, 4, 5, 6, 7, 8] is hard-coded. If you add page-9 and tab-9 but forget to add 9 to it, your tab button will do nothing at all when clicked — no error, no console message, just a dead button. This is the number one mistake when adding a tab.

SECTION 03

The four edit points

Adding any tab is always these four edits, in this order. The first three are mandatory for every tab; the fourth depends on your content.

EDIT 1 · REQUIRED Tab button Add one <button> to .tabs-bar
EDIT 2 · REQUIRED Content panel Add one <div class="page-panel" id="page-N"> inside .content
EDIT 3 · REQUIRED Register the number Add N to the array in setPage(). Skip this and the button is dead.
EDIT 4 · IF NEEDED New toggles or CSS Only if your tab uses a collapsible table or a component that doesn't exist yet
SECTION 04

Building the Q&A tab

Our new tab is number 9 — there are eight today: Brand, Key Accounts, GP %, Retention, Segmentation, Expenses, Net Profit, Staff.

4.1 — Add the tab button

Find the .tabs-bar block. It ends with the Staff button. Add yours as the last line before </div>:

  <button class="tab-btn" id="tab-8" onclick="setPage(8)"><span class="en">Staff</span><span class="zh">销售人员</span><span class="id">Staf</span></button>
  <button class="tab-btn" id="tab-9" onclick="setPage(9)"><span class="en">Q&amp;A</span><span class="zh">问答</span><span class="id">Tanya Jawab</span></button>
</div>
  • No active class. Only tab-1 carries it, because Brand is the tab shown on load. Never add a second one.
  • &amp; not &. A bare & starts an HTML entity. Q&amp;A is correct, and matches what the file already does for Boll &amp; Kirch.
  • Keep the label short. The bar is flex-wrap: wrap and position: sticky, so a long label wraps it onto an extra row that then sits pinned to the top of the screen on every scroll. One or two words.

Why this differs from the existing toggles

The existing toggleXxxTable() functions each hard-code one element ID. That works for eight tables, but not for twenty questions. This version takes the clicked button as an argument and toggles its parent, so one function serves every Q&A item — no new JavaScript when you add question twenty-one.

SECTION 05

The trilingual rule

Every string a user can read must exist in English, Chinese and Bahasa Indonesia. This is the rule most easily broken and the hardest to notice — a missing translation looks perfect in English and leaves a blank gap for a Chinese or Indonesian reader.

The mechanism is pure CSS. All three versions are always in the HTML; the body class decides which is visible.

.zh { display: none; }                  /* hidden by default */
.id { display: none; }
body.lang-zh .zh { display: inline; }   /* shown when 中文 picked */
body.lang-zh .en { display: none;   }
body.lang-id .id { display: inline; }
body.lang-id .en { display: none;   }

setLang() sets document.body.className to '', lang-zh or lang-id. The pattern you write is always three adjacent spans:

.en
Sales by Brand
.zh
按品牌划分的销售额
.id
Penjualan berdasarkan Merek

Inline vs block

UseWhenRenders as
.en / .zh / .idInside a sentence, label, table cell, headinginline
.en-block / .zh-block / .id-blockA whole paragraph or block elementblock

Rules of thumb

  • Never leave a bare untranslated string. The only exceptions in the file are proper nouns identical in all three languages — Boll & Kirch, staff names, GP %, currency figures — which sit outside the spans deliberately.
  • Keep the three spans adjacent, with no whitespace between them. Putting them on separate lines injects spaces into the rendered sentence.
  • Numbers aren't translated, but their punctuation is. English and Chinese use Rp 6,171,563,874; Indonesian uses Rp 6.171.563.874. The existing tabs follow this — match it.
  • Test all three before committing.

--text: #e8eaf0;   --muted: #8b8fa8;    --border: rgba(255,255,255,0.08);
--gold: #f59e0b;   --red: #f85149;      --green: #3fb950;
--series-1: #3987e5;  --series-2: #d95926;

Font family for any new button: 'Source Serif 4', serif. Buttons don't inherit it, which is why every button rule in the file restates it.

Charts are static HTML

There is no charting library. A bar is a div with an inline percentage width, computed by hand relative to the largest value:

<div class="bar-row">
  <div class="bar-label-row"><span class="bar-name">Dedeng Suryaman</span><span class="bar-value">Rp 3,584,174,562 · 17.5%</span></div>
  <div class="track"><div class="fill s1" style="width:100.0%">Rp 3.58B</div></div>
</div>

The largest bar gets width:100.0%; the rest are value / max × 100. Give zero-value bars width:0.5% so the row stays visible.

SECTION 08

Testing before you commit

No test suite exists, so this checklist is the test suite. Open the file directly in a browser — file:// works fine, nothing needs a server.

  • The new tab button appears in the tab bar, at the end of the row.
  • Clicking it shows your panel and hides the previous one. If nothing happens, you forgot step 4.3.
  • Every other tab still works — 1 through 9, in order. A stray unclosed </div> silently swallows the tabs after it.
  • Only one tab is highlighted at a time. Two highlighted means a duplicate active class.
  • Brand (Tab 1) is still the tab shown on page load.
  • Switch to 🇨🇳 中文 and read your whole tab. No English left behind, no blank gaps.
  • Switch to 🇮🇩 Bahasa — same check.
  • Switch back to 🇬🇧 English — no Chinese or Indonesian leaking through.
  • Q&A accordions open and close, and the + flips to −.
  • At phone width (~390px), the bar wraps onto more rows. Since it's position: sticky, every extra row permanently eats vertical space — check there's still room to read.
  • Browser console (F12) shows no red errors.

Quick structural sanity check from the terminal — the two counts must match:

grep -c 'class="tab-btn'    filtec-sales-dashboard.html
grep -c 'class="page-panel' filtec-sales-dashboard.html
SECTION 09

Committing and deploying

Work on a branch, never directly on main:

git checkout -b claude/add-qa-tab
git add filtec-sales-dashboard.html
git commit -m "Add Q&A tab: common questions on data sources and methodology"
git push -u origin claude/add-qa-tab

Then open a pull request against main. The site deploys from main, so merging is what publishes the change.

Commit message style

Follow the existing convention — a one-line summary, then a body explaining what was added and, crucially, what the data does and does not prove:

Add Staff tab: sales-order attribution by sales staff (#1)

Adds an eighth tab, Staff, to filtec-sales-dashboard.html covering sales-staff
attribution across all 230 Sales Orders: quotation ownership per staff (recorded
fact), derived per-order attribution with confidence bands (indicative), and
remediation steps for ERPNext.

Adds Chart 9, Chart 10, Chart 11 and Tables 1320, 1321, 1322 in the dashboard's
existing trilingual idiom.

Known limits, worth knowing but not required

  • No deep links. setPage() doesn't touch the URL, so you can't link straight to a tab. Reading location.hash on load would fix it — a change to shared machinery, so do it as its own commit.
  • Page <title> is fixed at “Filtec Sales Dashboard — Brand” and doesn't follow the active tab.
  • File size. At ~273 KB and 2,426 lines the single-file approach is nearing its comfortable limit. Splitting per-tab HTML is a significant refactor — worth discussing before tab 12, not while adding a tab.
